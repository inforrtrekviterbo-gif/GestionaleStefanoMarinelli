# Resi (reso / cambio) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reso/cambio avviabile anche dalla pagina Resi; la merce rientra a magazzino; il credito a favore del cliente diventa **sempre un buono** (mai contanti); l'eventuale differenza a suo carico si incassa con scontrino RT; massimo un reso per scontrino.

**Architecture:** Riuso del componente `ReturnForm` (già in Cassa) come mini-form nella pagina Resi; la riga reso viene precaricata in Cassa via `pendingCashAction` (come le prenotazioni). La logica soldi resta in `createSale`, generalizzando la generazione del "buono residuo" a tutti i resi con saldo negativo.

**Tech Stack:** Next.js 16, React 19, TypeScript, Postgres via shim, API `app/api/data/route.ts`.

**Verifica (niente test runner):** `npx tsc --noEmit` + `npx next build` (0 errori) + check manuale. Git: `/opt/homebrew/bin/git`. Commit a fine task.

**Spec:** `docs/superpowers/specs/2026-09-19-resi-design.md`

**Note riuso (già esistente):**
- `ReturnForm` (app/cash-register.tsx ~riga 488): ricerca reso via `view=returnReceipt` e `view=returnPrice`, costruisce una riga `itemType:"return"` (quantità negativa, `locked`, metadata con lo scontrino) e la passa a `add(item)`.
- `createSale` (route.ts): le righe `return` fanno `quantity += qtà` (rientro magazzino); esiste già la generazione del buono residuo SOLO per resi da buono (`total < -0.001 && returnGiftCodes.size`, righe ~740-754 e ~877-884). `expires_at` di gift_cards è già nullable.
- `pendingCashAction` (shell) → Cassa drena e precarica il carrello (già usato per prenotazioni).

Il componente `Returns` attuale ha firma `function Returns({ data }: { data: Bootstrap })`. Sostituirla con:
```tsx
function Returns({ data, goToCash }: { data: Bootstrap; goToCash?: (action: PendingCashAction) => void }) {
  const [query, setQuery] = useState("");
  const [showNew, setShowNew] = useState(false);
  const receiptById = new Map(data.sales.map((sale) => [sale.id, sale.receiptNo]));
  const returns = (data.saleItems ?? []).filter((item) => item.itemType === "return");
  const q = query.trim().toLowerCase();
  const visible = returns.filter((item) => `${item.description} ${receiptById.get(item.saleId) ?? ""} ${item.store}`.toLowerCase().includes(q));
  const store: Store = data.user.store ?? "Viterbo";
  function onReturnReady(item: ShellCartItem) {
    setShowNew(false);
    goToCash?.({ kind: "return", label: `Reso ${item.description}`, lines: [item] });
  }
  return <section className="screen"><div className="screen-head"><div><h1>Resi</h1><p className="muted inventory-intro">Registro dei resi e cambi. Avvia un nuovo reso: la merce rientra e il credito diventa un buono.</p></div><div className="head-controls"><button className="primary" onClick={() => setShowNew(true)}><MaterialIcon>sync_alt</MaterialIcon> Nuovo reso</button></div></div>
    <div className="panel"><div className="search-hero"><MaterialIcon>search</MaterialIcon><input value={query} onChange={(event) => setQuery(event.target.value)} placeholder="Cerca per prodotto, scontrino o sede…" /></div><div className="table-wrap"><table><thead><tr><th>Data</th><th>Sede</th><th>Prodotto reso</th><th>Qtà</th><th>Importo</th><th>Scontrino</th></tr></thead><tbody>{visible.length ? visible.map((item) => <tr key={item.id} className="return-row"><td>{dateTime(item.createdAt)}</td><td>{item.store}</td><td>{item.description}</td><td>{item.quantity}</td><td className="negative"><b>{money(item.lineTotal)}</b></td><td>{receiptById.get(item.saleId) ? <a href={`/api/pdf?type=receipt&id=${item.saleId}`} target="_blank" rel="noreferrer">{receiptById.get(item.saleId)}</a> : "—"}</td></tr>) : <tr><td colSpan={6}><Empty>Nessun reso registrato.</Empty></td></tr>}</tbody></table></div></div>
    {showNew && <Modal title="Nuovo reso" wide onClose={() => setShowNew(false)}><ReturnForm store={store} add={onReturnReady} close={() => setShowNew(false)} /></Modal>}
  </section>;
}
```
NOTA: `ReturnForm`'s `add` prop ha tipo `(item: CartItem) => void` dove `CartItem` è quello di cash-register (= `ShellCartItem`). `onReturnReady` usa `ShellCartItem` — combacia. Verificare che `Store`, `Modal`, `Empty`, `MaterialIcon`, `money`, `dateTime` siano in scope (sì).

- [ ] **Step 1: Build pulito** — Run: `npx tsc --noEmit && npx next build` → 0 errori.

- [ ] **Step 2: Checklist manuale (account test = sandbox)**

Serve prima una vendita con un prodotto (per avere uno scontrino da rendere).
- **Resi → Nuovo reso**: cerca lo scontrino / scan EAN → prezzo pagato corretto → "Aggiungi reso al cambio" → si apre la Cassa con la riga reso.
- **Reso puro**: Completa → in **Buoni** compare un buono del valore reso ("Buono al portatore" se nessun cliente); in **Magazzino** la giacenza del prodotto reso è aumentata; nessun contante.
- **Cambio più economico**: in Cassa aggiungi un prodotto che costa meno del reso → Completa → buono della differenza.
- **Cambio stesso importo**: prodotto pari → Completa → nessun incasso, reso registrato.
- **Cambio più caro**: prodotto più caro → Completa → scontrino della differenza; nelle righe/nel PDF compare il reso.
- **Max 1 reso**: apri Cassa → Operazioni → Reso/Cambio e prova ad aggiungere un secondo reso → viene bloccato.
- Entrata **Cassa → Operazioni → Reso/Cambio**: stessa logica (buono sul saldo a favore).
- TEST mode: nessuna scrittura.
